# Stale claims in the current PR #1 title and body (checked against head f7aa459)

1. **Title:** "data-oriented volume/snapshot lifecycle over gRPC" is now incomplete. The PR also ships NFS export, a CSI controller, Reconcile/GC, and systemd and Kubernetes deployment.
2. **"uses democratic-csi as the behavioural baseline"** is false. ADR 0003 made OpenZFS the source of truth, and democratic-csi is now one adoption target.
3. **"reads and writes the same `democratic-csi:*` user properties, so volumes democratic-csi already provisioned are picked up without migration"** is false. The default prefix is `zfs-endpoint`. Adoption requires `-property-prefix democratic-csi`, and without it a parent carrying only `democratic-csi:*` markers exits 78 at startup.
4. **"Reads `zfs get -Hp` output into a flat column buffer"** is false. Scan, Get and List now read `zfs get -j -p` JSON through one strict decoder streamed from the pipe. The text parser was removed.
5. **"Checked against OpenZFS source in three audits; anything it doesn't model is listed in its header"** is outdated. The simulator is now also checked by a `zfs(8)` reference model (`zfsdiff`, `FuzzDiff`) and against a real 2.4 pool (`TestRealFacts`).
6. **"serving on a unix socket with mode 0600"** is incomplete and misleading. There are now two sockets: a CSI-role socket (0600, or 0660 with `-socket-group`) and an admin socket (`-admin-listen`, root or the daemon's uid, by SO_PEERCRED) that carries Reconcile and the export RPCs.
7. **"alignment of 495 operations across 13 implementations"** is miscounted. It is 108 distinct operations, giving 495 mappings.
8. **"`FuzzParseColumns`: no crashes"** is false. That target no longer exists. The current targets are FuzzDecodeGetJSON, FuzzClassify, FuzzDiff, FuzzCreateConverges, FuzzReconcileSafe, FuzzModel, FuzzSimulateDestroyAllEquivalent and four FuzzNFS* targets.
9. **"`FuzzCreateConverges`: about 700k execs, no violations"** is a stale one-off figure. Fuzzing now runs in the nightly tier (5 min per target), and that tier has never run.
10. **"Real ZFS: not yet run."** is false. Three real-ZFS VM jobs run on every push.
11. **"The CI job `real-zfs` creates a file-backed pool"** is outdated. It is now three jobs (`endpoint 0/2`, `endpoint 1/2`, `csi`), each in an Ubuntu 26.10 KVM guest with OpenZFS 2.4, using sharded pools on sparse files in guest tmpfs. csi-sanity runs there too.
12. **"This PR is the first time it will run."** is false. It has run on every push for the whole day.
13. **Testing section, by omission:** it does not mention `TestModel`, the FSM explorer, nightly, cache-warm, the skip/split checks, or the 60 s CI budget (ADR 0005).
14. **"Not in this PR: NFS/SMB/iSCSI/NVMe-oF exports"** is false for NFS, which ships. SMB and block export are still absent.
15. **"Not in this PR: A CSI front end"** is false. `internal/csi` and `cmd/zfs-csi` (Controller and Identity) ship.
16. **"Not in this PR: Transport auth (the socket is mode 0600 until then)"** is partly false. ADR 0001 v2 roles per listener and peer credentials are built. Only mTLS/TCP is not.
17. **"Not in this PR: Reconcile/GC"** is false. The Reconcile RPC, the `zfs-endpoint reconcile` CLI and the daily report-only timer ship.
18. **"Not in this PR: HA fencing"** is still true, but the framing is stale. Fencing was designed and then dropped, and per-host `flock` is the decision.
19. **What's here, by omission:** it does not list `internal/csi`, `internal/nfsref`, `internal/unixsock`, `internal/version`, `internal/leakcheck`, `cmd/zfs-csi`, `deploy/`, `ci/`, `.github/workflows/`, `CONTEXT.md` or `docs/adr/` (8 ADRs).
20. **Footer:** it uses a "_Generated by [Claude Code](...)_" line instead of the required attribution block.

Still accurate: the scan/plan/apply description, an empty plan for a repeated request, `ABORTED` before the caller's deadline, buf STANDARD lint with a Capabilities RPC (`GetCapabilities`), the empty root commit on `main`, and the README's record of disproved claims.
