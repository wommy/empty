ci: fall back to proxy.golang.org when the Go release download fails

Nightly run 42470850520 lost all 7 jobs at "install Go 1.27.3": the
actions/go-versions release host returned 502/504 and curl exited 56
(Connection died). Job 128708585422 showed a worse failure: the primary
curl hung without failing, so the install step's 60s wait expired while
curl was still running and no fallback could start.

The start step now tries the primary exactly as before. If any part of
it fails, it removes any partial $HOME/sdk/go and downloads the
golang.org/toolchain v0.0.1-go1.27.3.linux-amd64 zip from
proxy.golang.org, verifies it against GO_PROXY_SHA256
(af4c06478303fdd1bfb335fab86c7ccb9b12e529044a946a16a1c4bcc779f8d7),
and moves its toolchain directory into place. The log records which
source was used.

Timeouts: each curl is capped twice. --max-time and --connect-timeout
apply per attempt, and --retry 3 retries timeouts, so each attempt alone
could run for minutes. An outer `timeout` caps the whole curl including
retries: 45s for the primary and 60s for the fallback. A capped attempt
exits non-zero, so the fallback starts. Worst case is about 110s,
inside the install step's 480 x 0.25s = 120s wait.
