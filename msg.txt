endpoint: etab fuzz precondition refuses a path mountd cannot read

Nightly FuzzNFSEtabParse run 42805096797 (job 129792079804) failed on an
etab whose first line is a 3849-byte path ("X" * 3840, then "/tank/v/a")
followed by "/tank/v/a\t10.0.0.0/24(ro)". The verifier said 10.0.0.0/24
is served ro, while mountd's model gives /tank/v/a no export.

Both sides are right for etab as written. getpath reads the path with
xgettok(pathTokSize), where pathTokSize is NFS_MAXPATHLEN+1 (nfslib.h:85).
When the token reaches the size, xgettok returns -1, getpath returns it,
next() returns nil, and export_read stops reading the file
(exports.c:940-945, export.c:122). mountd never reads the second line.
ParseEtab skips the bad line and keeps the second.

This etab cannot come from exportfs. exportfs loads entries through the
same getexportent, so their paths are at most 1024 bytes once escapes are
decoded, and putexportent writes them back out. etabAsWritten admitted
the line because it checked the path's characters but not its length.
The earlier fix e8dd478 (optionsAsWritten) closed the same kind of gap.

pathTokenReadable replays xgettok on the written path: each byte is
appended, a completed \ooo collapses to one byte, and the loop ends while
the token is still below the size. A raw escape whose digits reach the
size before they collapse is refused, as xgettok refuses it.

The reproducer is seeded as testdata/fuzz/FuzzNFSEtabParse/c5382d054888949b
with data {0, 2}. The original seed data {1, 0, 0, 0, 4, 1} does not
reach the failing client and passes on the unfixed code.
TestEtabAsWrittenMatchesMountd checks the rule against nfsref.LoadEtab for
paths around the limit and for an escape at it.

Limit of this change: the claim above covers this reproducer. The exact
mirror also refuses some lines putexportent can write, for example a path
near 1024 bytes whose escapes push its written form past 1024 bytes. For
those, mountd also cannot read the line, so this may be a real
ParseEtab/mountd divergence that the precondition now hides. It is not
decided here.
