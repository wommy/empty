## Top 5

1. D1/B8: No node service anywhere in the repo, yet fs-on-zvol expansion reports node_expansion_required=true (controller.go:365; identity.go:42-52). Deployment pairing is UNVERIFIED and is the biggest operator risk.
2. A3/D6: sparse/reserve refusal across kinds (plan.go:101-105) blocks a single StorageClass; the endpoint's properties map is advertised but unreachable from CSI (controller.go:261-265).
3. B5: GetCapacity ignores volume_capabilities and parameters, which the spec says SHALL be taken into account (controller.go:331-337); democratic-csi returns 0 for unsupported caps.
4. B15/D2: Probe returns the endpoint's code unchanged (UNAVAILABLE, not FAILED_PRECONDITION) and never checks the pool (identity.go:54-60).
5. B9/B10/D5: unlimited (adopted) filesystems report capacity 0 and make a repeat CreateVolume with a size return ALREADY_EXISTS (table.go:44-50; plan.go:293-296; controller.go:364).

Also worth tracking: B12 (malformed DeleteVolume id → INVALID_ARGUMENT, spec says OK), B13 (unmanaged dataset delete loops with FAILED_PRECONDITION), B2 (ListSnapshots hides unmanaged snapshots), C2 (plain ctx errors map to Internal, not Canceled/DeadlineExceeded).
