# 1. Transport, tenancy and per-RPC authorization (v2)

Status: draft (wave 11) · Date: 2026-10-27 · Supersedes: ADR 0001 v1 (proposed, never built). Related: ADR 0003, ADR 0004, ADR 0005, `wave11/threat-model.md`.

## Context

**What is built** (HEAD `4c1386e`):
- One daemon per parent dataset (`zfs-endpoint@<parent>.service`).
- `flock` refuses nested or duplicate parents on one host.
- Scans are depth-1 under the parent. Ids are relative to it.
- The socket is 0600 root, in `/run/zfs-endpoint` (0700). The same directory holds every instance's socket and lock files.
- TCP is refused by both binaries. Abstract sockets are refused.
- Every caller can call all 11 RPCs. No peer identity is read or logged.

**What v1 decided and why it stalled:**
- v1 decided: `SO_PEERCRED` for unix, mTLS for TCP, and a policy file of principals, each with an RPC allowlist and a `volume_prefix` scope.
- It stalled for four reasons:
  1. Per-volume scoping has to be enforced in every planner entry point. One that is forgotten fails open (v1's own "known risk").
  2. Root pods all look like `uid=0`, so per-uid policies cannot separate the commonest front ends.
  3. "Several clusters share one parent" contradicts Reconcile. Its desired set is complete per parent, so each cluster's GC would collect the other's volumes.
  4. No remote front end exists. zfs-csi needs a hostPath to the socket, so it always runs on the storage host.

**What the threat model found** (wave 11):
- A pod given the socket directory can do four things: reach every instance, hold any instance's lock (blocking its restart), replace sockets, and call Reconcile or PublishFileExport, which zfs-csi never uses.
- Reconcile accepts `unlimited_deletions` with no digest.

## Decision

### 1. The tenancy unit is the parent dataset

- One tenant (a cluster, a driver deployment or a StorageClass family that must be isolated) gets its own parent, its own instance and its own socket directory.
- Isolation between tenants comes from things OpenZFS and the kernel already enforce:
  - the dataset subtree;
  - directory permissions on the socket;
  - which hostPath the kubelet mounts into which pod.
- No in-process volume scoping is built. The CSI ids, Reconcile's desired set and GetCapacity are all per parent, so they are correct by construction.
- One parent has exactly one container orchestrator (CO). Reconcile's contract states it: "the desired set is complete for the parent".

### 2. Socket layout

```
/run/zfs-endpoint/                 0700 root   locks only, never mounted into a pod
/run/zfs-endpoint/sock/<inst>/     0750 root:<group>  csi listener (endpoint.sock, 0660)
/run/zfs-endpoint/admin/<inst>/    0700 root   admin listener (endpoint.sock, 0600)
```

- The daemon refuses with exit 78 in two cases:
  - a listener whose directory is the lock directory, or contains it;
  - two listeners in one directory.
- systemd: `RuntimeDirectory=zfs-endpoint zfs-endpoint/sock/%i zfs-endpoint/admin/%i`.
- `-socket-group <name|gid>` sets the csi socket to 0660 with that group. The controller pod then runs **non-root**, with `supplementalGroups: [gid]`, and mounts only `sock/<inst>`. Without the flag the socket stays 0600 root (today's behaviour).

### 3. Roles per listener, not a policy file

- A unary interceptor holds a table keyed by every method in `EndpointService_ServiceDesc`:

  | Role | Methods |
  |---|---|
  | `csi` | GetCapabilities, CreateVolume, DeleteVolume, ExpandVolume, GetVolume, ListVolumes, CreateSnapshot, DeleteSnapshot, ListSnapshots, GetCapacity |
  | `admin` | everything, including Reconcile, PublishFileExport and UnpublishFileExport |

  - A method missing from the table is denied. A test fails when an RPC is added without a row.
  - Health is served on both listeners.
- `-listen` serves `csi`. `-admin-listen` serves `admin` and is optional. Without it, Reconcile and the export RPCs are unavailable and return `PERMISSION_DENIED`.
- When CSI ControllerPublish lands, `csi` gains Publish and Unpublish with one constraint: the client must be a `/32`, matching ADR 0004's "node_id is a single host".

### 4. Peer credentials: logged now, authorized optionally

- A `TransportCredentials` handshaker reads `SO_PEERCRED` on every unix connection and exposes `{uid, gid, pid}` as `AuthInfo`. A connection that is not unix is refused with `UNAUTHENTICATED`.
- Every RPC log line carries `peer_uid`, `peer_gid` and `peer_pid`.
- An optional per-listener `-allow-uids` set exists. An empty set means "filesystem permissions only".
- The credentials are those in effect at `connect(2)`. Once uids are authorized, `MaxConnectionAge=1h` bounds a revoked uid.

### 5. Destructive guards in Reconcile

- A run that collects any undesired volume requires `plan_digest` from a dry run. Without one it returns `FAILED_PRECONDITION`.
- An undesired volume that is exported (`sharenfs` not `off`, or a non-empty client list) is skipped with "exported: in use".
- A two-person approval (`ApproveReconcile` by a principal different from the caller) is **not** built. It is revisited once callers have distinct principals.

### 6. TCP

- TCP stays refused.
- When a remote front end is needed, v1's mTLS design applies to a TCP listener with a role:
  - TLS 1.3, `RequireAndVerifyClientCert`;
  - exactly one URI SAN as the principal;
  - explicit CA, or SPIFFE `X509Source`;
  - reload on SIGHUP and an mtime poll;
  - `MaxConnectionAge`.

  Pick it up then. Nothing of it is built now.

### 7. Audit

- The unit sets `LogRateLimitIntervalSec=0`, so a flood of cheap calls cannot push destroy lines out of journald.
- `request_id` is always minted by the server. A caller's id is logged as `client_request_id`.
- Shipping logs off the host is a deployment recommendation, and `Seal=yes` is optional.

## Consequences

- **More instances.** Tenants that would have shared a parent now get one each. That means more systemd units, sockets and datasets. Capacity is still shared at the pool level (GetCapacity reports pool free space unless the parent has a quota). Operators should set `quota` on each tenant parent.
- **The zfs-csi deployment changes.** It mounts `/run/zfs-endpoint/sock/<inst>` and dials `unix:///run/zfs-endpoint/sock/<inst>/endpoint.sock`. With `-socket-group` it runs non-root.
- **Smaller blast radius.** A compromised controller pod is limited to its own parent and to the `csi` methods. It loses export-to-self, mass Reconcile, lock DoS and socket replacement.
- **No policy file** means no new source of truth outside ZFS to keep in sync across an HA pair, which was v1's known risk. Roles are flags in the unit.
- **Shared parents need a new ADR.** If an operator truly needs several COs on one parent, this ADR cannot serve them. That case needs scoped Reconcile and is deferred.

## Alternatives considered

| Alternative | Why not now |
|---|---|
| v1: a policy file with principals, RPC allowlists and `volume_prefix` | Enforcement is split and fails open. It is incompatible with desired-set Reconcile. Root pods are indistinguishable. It costs the most, and it adds a source of truth outside ZFS. |
| Keep one socket and authorize by `SO_PEERCRED` uid only | Every root pod is `uid=0`. The userns translation of uids with idmapped mounts is unverified. It does not stop lock or socket tampering through the shared directory. |
| mTLS on the unix socket as well | Every local front end needs a cert, which is heavy for the single-host case, and it does not fix the directory sharing. |
| A separate daemon (a privileged helper) for destructive operations | Two root daemons, a second protocol and drift between them. Listener roles give the same separation inside one process. |
| A unix socket per RPC | Too many hostPaths and no gain over two roles. |
| A keyed approval token (HMAC) on the digest | It needs a key, which means key storage and rotation, and it still does not prove a *second* person without principals. Defer it with the two-person rule. |

## Testing (ADR 0005: lowest level that proves it)

- **Pure:**
  - the role table against `EndpointService_ServiceDesc`: complete, and every method has an explicit role;
  - `socketDirs()` refuses the lock directory, its ancestors and duplicate directories.
- **`internal/server` over bufconn** with a fake `AuthInfo`, as a table of `role × method → OK | PERMISSION_DENIED`. A missing AuthInfo returns `UNAUTHENTICATED`.
- **`internal/server` on a real unix socket in `t.TempDir()`:**
  - `peer_uid == os.Getuid()` appears in the log record;
  - `-allow-uids` without our uid gives `UNAUTHENTICATED`.
- **The root VM job:** a child with `Credential{Uid: 65534}` cannot open the 0600 admin socket. With `-socket-group`, a member gid succeeds on csi and fails on admin.
- **Planner:**
  - an exported, undesired, aged volume is skipped;
  - an undesired collection without a digest is refused.
- **A unit lint test** parses `deploy/systemd/zfs-endpoint@.service` for `RuntimeDirectory`, `LogRateLimitIntervalSec=0` and the hardening set.
